# Open questions

Ordered by potential rework.

1. **Default fidelity floor.** A permissive default recreates a pixel-shaped
   lowest common denominator; a strict one makes simple work noisy. E1 records
   fidelity but does not choose the product default.
2. **Footprints through discontinuous/nonlinear maps.** A Jacobian is only
   first-order. Determine when subdivision, interval bounds, or stochastic
   sampling is required.
3. **Schema evolution.** Define stable intent identifiers and migrations before
   Phase 2 graphs become user documents.
4. **Topology.** Cross-representation topology has no honest portable algebra.
   Keep it `Native` until a real shared operation forces a core concept.
5. **Non-Euclidean cost.** General charts are correct but may miss every GPU
   fast path. Measure before specializing the core.
6. **Fidelity composition.** E1 uses an ordered error class; later plans may need
   quantitative and task-specific bounds without pretending unlike errors add.

None blocks E1.
