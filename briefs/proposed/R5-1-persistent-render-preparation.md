# Proposed R5-A: retain render preparation across camera edits

**Rank 1 · Owner: Rendering lane (L4).** Fluids supplies the existing baked Hot pour/cache format as input; this brief makes no solver changes. Proposed 2026-10-20; effort **3–5 engineering days**, Lane 3 estimate, not a performance promise. Research: [interactive volumes](../../docs/INTERACTIVE_VOLUMES_LIQUIDS.md), Parts 1 and 2 (Cycles/Karma persistent preparation, NanoVDB immutability).

## Goal and scope

Remove repeat camera-independent work from warm views and refinement without changing pixels. First profile the exact shot; the assignment's first-look delay has not been partitioned. Own `pathtrace.py`, `gpupathtrace.py`, renderer-side preparation/cache code and focused tests. Do not change fluid solver output, schema, shared UI, or introduce a native NanoVDB backend.

## Deliver, in order, with a commit per part

1. Add a reproducible Hot pour mode to the existing timing harnesses and collect the pre-change decomposition under the common contract below. Record build/pack counters and cache bytes in addition to time. Identify shadowcatch wrapper renders and guide passes separately; do not claim they are one trace. Preserve the current furnished/mixed controls.
2. Separate camera-independent mesh/volume preparation from camera-dependent rays/splat normals. Extend `pathtrace.build_scene` reuse beyond its current per-build BLAS dictionary, and `gpupathtrace.reusing_scene` beyond its current eye-keyed, scope-limited preparation. Use immutable scene/data revisions, strong references and bounded byte accounting; an `id` alone or silent mutable-array aliasing is insufficient. Reuse `_Frame` buffers already present. Invalidate on geometry/topology/material-density/settings edits as appropriate, device loss and cache eviction. Preserve camera-dependent splat work. Count avoided builds rather than assuming a camera key change did nothing.
3. Prove no stale reuse: camera edits retain geometry; topology and density changes rebuild affected structures; transform-only updates leave local geometry intact; extinction edits rebuild bounds; light edits reset radiance without rebuilding unchanged geometry. Cover frame forward/back, bounded eviction, cancelled work, allocation release and CPU fallback. Measure post-change against the exact baseline and publish results.

## Targeted tests and decision

Start with `tests.test_gpu_frame_reuse`, `tests.test_3d_first_look`, `tests.test_3d_progressive_job`, `tests.test_3d_pathtrace_volumes`, `tests.test_sparse_gpu_volumes`, plus new invalidation tests and existing shadowcatch tests found by source search. Run GPU-bearing tests on all required adapters. Pass identical fixed-sample pixels within existing tolerances; a timing win cannot excuse wrong geometry/alpha. Potential first-look saving is bounded by measured removable preparation, so this part may legitimately leave the overall target unmet. Supply that remaining phase budget to R5-B and R5-C.
